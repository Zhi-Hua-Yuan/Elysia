- Windows 环境、Python/uv 环境和本地忽略配置可正常运行。
- 麦克风、浏览器 VAD、Sherpa-ONNX SenseVoice ASR、OpenAI-compatible
  LLM、TTS、字幕和 Live2D 已形成完整对话链路。
- Live2D 音量嘴型、表情 payload、表情标签清理和播放中打断已人工通过。
- 10 轮连续语音对话、桌宠透明/置顶/拖拽/缩放已人工通过。
- 已增加按 `turn_id` 关联的 ASR、LLM 首句、TTS、首段 payload 和前端播放
  延迟日志；日志不记录 Prompt、对话正文、Endpoint 或凭据。
- 默认 MVP-A TTS 已从 Edge TTS 调整为 Sherpa-ONNX 本地通用女声；
  Edge TTS 作为在线回退保留。
- Sherpa-ONNX 路径 10 轮首段播放 p50 为 4096.0 ms，首段成功率 10/10，
  达到 p50 不超过 5000 ms 的门槛。
- 配置日志的 API Key 泄露风险已经修复，受影响的旧日志和旧 Key 已处理。
- 后端 MIT、Web/Electron 前端独立许可证、Live2D 独立条款的边界已经明确。

完整证据和性能数据见 [`elysia-m0-acceptance.md`](elysia-m0-acceptance.md)。

详细记录见 [`elysia-m1-acceptance.md`](elysia-m1-acceptance.md)。

## 后续里程碑

核心链路已在 M0 通过，M2 只处理交付质量：

- [x] M2.1：核对 Electron 安装包与冻结前端子模块的真实版本关系。
  两者均来自前端源码提交 `3d57a9a`，不同资源名属于不同构建目标的正常结果。
- [x] M2.2：处理并验收识别设置保存与持久化问题。
- [x] M2.3：固化环境、配置和模型准备说明，并使用占位 Live2D 与
  Sherpa-ONNX 通用声音完成一次从无密钥模板开始的可重复演示。
- [x] M2.4：建立简短的启动冒烟清单和常见故障排查表；三轮短验收和
  后端正常退出均已通过。
- [x] M2.5：完成自动化回归、配置、文档、Git 忽略、敏感信息和许可证
  边界检查；M2 正式关闭。

M2 退出条件：新建本地配置后可按文档独立启动；完整语音链路与打断可复现；
仓库不包含密钥或专有资产；已知非阻塞问题均有明确说明。

### M3：MVP-B 正式角色资产接入

前置条件：用户提供有权本地使用的 Live2D、GPT-SoVITS 权重、参考音频及
必要文本。资产继续位于 Git 忽略目录，不纳入代码仓库。

- 接入 `elysia-local` Live2D，核对 Cubism 版本、模型 URL、缩放、Idle
  Motion、表情文件、名称和索引。
- 完成 `model_dict.json` 本地元数据和至少 3 种可辨识表情映射。
- 启动独立 GPT-SoVITS 服务，优先验证现有 `gpt_sovits_tts` 适配器。
- 验证音频格式、参考音频路径、超时、服务离线和错误提示。
- 使用同一性能口径测试角色音色；本机 CPU 不达标时，将服务移动到用户
  控制的局域网 NVIDIA 主机，Open-LLM-VTuber 协议保持不变。

M3 退出条件：正式 Live2D、正式音色、嘴型和至少 3 种表情完成端到端验收；
首段播放 p50 目标仍为 5 秒；专有资产和凭据均未进入仓库。

### M4：MVP 冻结与收尾

- 汇总安装、启动顺序、配置字段、资产契约、性能结果和故障排查。
- 运行完整自动化回归和最终人工验收清单。
- 复核后端、前端、Live2D、声音模型及角色资产许可证边界。
- 修复验收暴露的最小问题，冻结 MVP 版本并形成可回退的 Git 标记或发布点。
- 将 Memory、MCP、Agent、Computer Use 等转入下一阶段独立设计，不在
  MVP 收尾期间顺带实现。

M4 退出条件：项目可按文档重建和演示；自动化测试通过；第一阶段已知问题、
性能数据和资产责任边界均有记录。

## 近期执行顺序

继续遵循“一次推进一个可验证步骤”：

1. 等用户提供有权本地使用的 Live2D、GPT-SoVITS 权重和参考音频。
2. 资产到位后先建立 M3 本地资产清单和接入契约。
3. 不提前为未知模型假定表情索引、Motion 组或音色性能。
