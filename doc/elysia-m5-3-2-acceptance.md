# Elysia M5.3.2 业务增删改查与备份处理验收

更新日期：2026-08-13

当前状态：**实现与自动化验收通过**。

## 固定范围

本里程碑基于 M5.3.1 的结构化命令与内容策略契约，实现持久记忆业务
增删改查、去重、容量、revision 冲突和破坏性操作后的备份脱敏。

- 不调用自然语言命令解析器；
- 不接入 `ServiceContext`、单人对话、Agent 或 WebSocket；
- 不保存连接级清空确认状态；
- 不生成角色回复或 TTS；
- 不实现前端记忆管理界面；
- 不开放群聊、代理模式或多用户记忆。

## 实现结果

### 业务服务

- [x] `PersistentMemoryService` 新增结构化 `list_items`、`upsert_item`、
  `delete_item` 和 `clear_items`；
- [x] 新增不携带记忆正文的 `MemoryMutationResult`，区分实际修改与幂等成功；
- [x] 新增内部 `MemoryListResult`，并约束失败结果不得携带条目；
- [x] 查询结果按称呼、偏好、重要事实和更新时间确定性排序；
- [x] 称呼只保留一条，更新时保留原 `id` 和 `created_at`；
- [x] 非称呼条目按规范化内容跨偏好/重要事实去重；
- [x] 幂等重复不写文件、不增加 revision、不占用新容量；
- [x] 非称呼 key 使用类别和 SHA-256 摘要，不包含用户正文；
- [x] 写入前在 Service 层再次执行 M5.3.1 内容策略；
- [x] 容量满时拒绝新增，但允许称呼更新、删除和清空；
- [x] 删除采用完整相等优先、唯一包含匹配次之的确定性规则；
- [x] 无匹配返回 `not_found`，多匹配返回 `ambiguous_match`，不猜测删除；
- [x] 空文档清空为幂等成功，不增加 revision；
- [x] 清空严格校验调用方提供的 `expected_revision`，不自动重试；
- [x] 成功写入后立即更新文档缓存，失败时不以期望文档污染缓存。

### 并发与 revision

- [x] 同一 Service 中每个作用域使用异步锁串行执行业务写操作；
- [x] 不同 Service 或外部写入继续由 Store revision CAS 防护；
- [x] 普通新增、更新和删除在首次 CAS 冲突后强制重载并完整重算一次；
- [x] 第二次 CAS 冲突返回稳定 `revision_conflict`；
- [x] 清空遇到 revision 变化立即失败，避免删除确认之后的新条目；
- [x] 每次实际写入 revision 只增加一次，幂等操作保持原 revision。

### 备份脱敏

- [x] Store 新增 `PREVIOUS` 和 `REPLACEMENT` 两种备份模式；
- [x] 普通创建继续保留前一有效版本；
- [x] 更新、删除和清空使用 replacement 模式，使主文件和备份都只包含新文档；
- [x] 成功删除或清空后，被移除正文不能从 `.bak` 恢复；
- [x] 主文件后续损坏时只能恢复脱敏后的新版本；
- [x] 备份替换失败时不触碰主文件；
- [x] 主文件替换失败时回滚备份到当前有效版本，并且操作不返回成功；
- [x] 所有失败路径清理同目录临时文件。

## 退出结论

M5.3.2 的退出条件已经满足：结构化业务 API 可以可靠地查询、新增、更新、去重、
删除和清空记忆；容量、并发和 revision 规则已经固化；更新、删除或清空成功后，
旧正文不会继续保留在恢复备份中。
