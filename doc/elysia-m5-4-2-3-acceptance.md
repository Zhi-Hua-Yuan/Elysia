# Elysia M5.4.2.3 管理控制器验收

更新日期：2026-08-14

当前状态：**实现与自动化验收通过**。

## 1. 固定范围

本步骤基于 M5.4.2.1 冻结的 WebSocket v1 协议和 M5.4.2.2 严格管理
CRUD，实现协议模型与业务服务之间的应用层管理控制器：

- 从服务端运行状态构造可信管理上下文；
- 统一执行本机、代理、群聊、Agent 和作用域资格检查；
- 将状态、列表、添加、编辑、删除和清空请求映射到记忆业务服务；
- 将内部状态和原因码映射为冻结的 v1 响应；
- 为总开关更新定义独立的配置持久化端口；
- 在 `ServiceContext` 提供类型化管理请求入口；
- 管理修改使 M5.3 待确认语音清空失效。

本步骤不解析原始 JSON，不注册 WebSocket 消息路由，不实现配置文件持久化，
也不实现前端管理界面。依赖基线提交：`a663844`。

## 2. 实现结果

### 2.1 可信上下文与访问边界

- [x] 客户端不能指定 profile、角色、存储路径、容量、来源或内部 key；
- [x] 作用域只由当前 `ServiceContext` 的 `profile_id` 与 `conf_uid` 推导；
- [x] 访问拒绝顺序固定为非本机、代理、群聊、不支持 Agent、非法作用域；
- [x] 被拒绝的请求不会读取存储，也不会泄漏开关、数量或 revision；
- [x] 只有 `basic_memory_agent` 可以进入管理业务层；
- [x] 异常日志只记录操作类型和异常类型，不记录正文、路径或完整请求。

### 2.2 状态、列表与禁用态

- [x] 状态响应按冻结能力矩阵生成，不由客户端能力声明决定；
- [x] 存储可用时返回 item count、max items 和 revision；
- [x] 存储不可用时隐藏 item count 与 revision，并返回 `storage_failure`；
- [x] 列表只投影 ID、类别、正文、来源和 UTC 时间，不暴露内部字段；
- [x] 总开关关闭后仍允许状态、列表、删除和清空；
- [x] 总开关关闭后添加和编辑返回 `memory_disabled`；
- [x] 对话读取、显式语音写入和 Prompt 注入继续受原 `enabled` 门控；
- [x] 禁用态初始化管理服务不会提前创建存储目录。

### 2.3 严格 CRUD 映射

- [x] 添加、编辑、删除和清空分别调用 M5.4.2.2 的严格业务方法；
- [x] `expected_revision` 原样进入业务层，控制器不自动重试冲突；
- [x] 响应 `operation` 保留客户端请求语义，Upsert 幂等命中不改成 update；
- [x] 成功结果映射 changed、memory ID、revision 和 item count；
- [x] 业务拒绝映射为 `rejected`，存储或未知故障映射为 `failed`；
- [x] 未知业务原因与不可预期异常统一降级为 `internal_error`；
- [x] 所有失败响应均不携带记忆正文或异常正文。

### 2.4 开关端口与生命周期

- [x] `expected_enabled` 与服务端当前值不一致时返回 `setting_conflict`；
- [x] 请求值等于当前值时幂等成功，不调用配置端口；
- [x] 实际切换通过 `MemorySettingUpdatePort` 隔离配置持久化；
- [x] 端口尚未接入时返回 `config_persist_failure`，不会假装修改成功；
- [x] 任一管理修改请求都会清除 M5.3 待确认语音清空状态；
- [x] 只读状态和列表请求不会清除待确认状态；
- [x] 管理请求不调用 Agent、不产生语音、不写聊天历史。

## 4. 退出结论

M5.4.2.3 已形成独立、可测试的记忆管理应用层：它只接受冻结的类型化请求，
只信任服务端派生上下文，统一执行资格检查、禁用态能力控制、严格 CRUD 调度
与脱敏错误映射；同时保持 M5.3 对话链路的总开关语义不变。

后续 WebSocket 接入只需负责原始消息解析、版本与非法请求错误封装及终态响应
发送；配置持久化步骤负责实现并注入 `MemorySettingUpdatePort`。这两部分仍应与
本控制器分层实现和验收。
