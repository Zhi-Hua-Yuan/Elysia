# Elysia M5.4.2.4 WebSocket 接入验收

更新日期：2026-08-14

当前状态：**实现与自动化验收通过**。

## 1. 固定范围

本步骤在 M5.4.2.1 冻结协议、M5.4.2.2 严格管理 CRUD 和 M5.4.2.3
管理控制器之上，完成记忆管理平面与现有 WebSocket 服务的传输层接入：

- 严格解析七类 v1 记忆管理请求；
- 将七类请求注册到同一个记忆管理 WebSocket 处理入口；
- 从服务端连接和群组状态派生可信管理上下文；
- 调用 `ServiceContext` 的类型化管理控制器入口；
- 将类型化响应序列化为一个终态 JSON 文本帧；
- 对协议错误、内部异常和发送失败执行脱敏处理。

本步骤不实现配置文件写盘，不实现前端管理界面，不改变聊天、TTS、Agent、
字幕、表情或历史记录链路。配置总开关的真实持久化仍属于 M5.4.2.5。

## 2. 实现结果

### 2.1 传输适配器

- [x] 七类冻结请求类型使用唯一集合和唯一操作映射；
- [x] 原始 payload 通过冻结的 Pydantic 请求适配器严格校验；
- [x] 未知字段、错误字段类型、非法 UUID 和缺失字段均返回 `invalid_request`；
- [x] 非 v1 严格整数版本返回 `unsupported_protocol_version`；
- [x] 无法信任的 `request_id` 在错误响应中固定为 `null`；
- [x] 类型化响应通过冻结的响应适配器序列化；
- [x] 传输适配器不读取存储、不执行 CRUD、不修改配置。

### 2.2 WebSocket 路由与可信上下文

- [x] 七类请求均注册到统一 `_handle_memory_management_request` 入口；
- [x] 只匹配精确消息类型，不使用前缀或模糊路由；
- [x] 本机资格从 WebSocket 对端数值 IP 推导，支持 IPv4 与 IPv6 loopback；
- [x] 主机名和不可解析地址不会被误判为本机；
- [x] 群聊状态从服务端连接组及成员数推导，客户端不能自行声明；
- [x] profile、角色和存储作用域继续由当前 `ServiceContext` 推导；
- [x] 处理器只调用类型化控制器入口，不直接访问记忆存储。

### 2.3 响应、异常与隐私

- [x] 每个已接收的管理请求最多发送一个终态响应；
- [x] 协议错误直接生成冻结的 `memory-management-result`；
- [x] 控制器异常统一降级为 `internal_error`；
- [x] 发送异常被当前处理器收口，不触发第二个通用错误响应；
- [x] WebSocket 断开异常保留既有断开生命周期；
- [x] 日志不记录记忆正文、原始 payload、路径或异常正文；
- [x] 只有成功的列表响应能够通过既有控制器返回记忆正文；
- [x] 管理请求不调用 Agent、不产生语音、不写聊天历史。

### 2.4 真实应用层往返

- [x] 使用真实 `ServiceContext`、管理控制器和临时存储完成状态查询；
- [x] 通过 WebSocket 路由完成创建请求并取得成功终态响应；
- [x] 随后的列表请求能够读回已创建条目；
- [x] 请求 ID、revision、条目数量和响应类型均保持协议一致。

## 4. 退出结论

M5.4.2.4 已完成冻结记忆管理协议到现有 WebSocket 服务的正式接入。传输层只负责
严格解析、可信连接上下文派生、控制器调度和单终态响应发送，业务规则继续收敛在
M5.4.2.3 控制器中，存储规则继续收敛在 M5.4.2.2 服务中。

下一步可进入 M5.4.2.5：实现并注入 `MemorySettingUpdatePort`，完成总开关的安全、
原子配置持久化；随后再接入 M5.4.3 管理界面。当前步骤没有进行浏览器端人工验收，
前端联调应在管理界面具备后单独执行。
