# Elysia MVP-B M3 角色资产接入契约

更新日期：2026-08-12

## 目的

本契约用于 M3“MVP-B 正式角色资产接入”。它规定 Live2D、本地声音权重、
参考音频、在线声音模型和相关文本进入运行环境前必须满足的权利、来源、
安全和技术条件，不代表任何具体资产已经获得授权。

M3 继续沿用“公开代码与本地专有资产分离”的原则：仓库可以提交接入代码、
无密钥配置示例、元数据模板和验收文档；实际角色模型、声音权重、参考音频、
本机路径及包含个人信息的授权证明不得提交。

## 资产状态

每项资产必须独立记录并使用以下状态之一：

| 状态 | 含义 | 是否允许进入正式 M3 |
|---|---|---|
| `approved` | 来源、使用范围和技术信息均已确认 | 允许，且只能在确认范围内使用 |
| `restricted` | 可以使用，但展示、修改、分发或商业使用受到限制 | 有条件允许，必须遵守限制 |
| `pending` | 来源或许可仍有未确认事项 | 不允许进入正式接入 |
| `rejected` | 来源不可信、许可不足或文件存在安全问题 | 不允许使用 |

Live2D 和声音资产分别判定。一个类别通过，不代表另一个类别自动通过，也不
要求二者同时到位。

## 权利与来源准入条件

每项资产至少记录：

- 资产名称、版本、来源链接、作者或提供者、获取日期。
- 作者与权利人是否一致；不一致时，提供者依据什么权利提供该资产。
- 是否允许本地个人使用、技术修改和格式配置。
- 是否允许录屏、直播或其他公开展示。
- 是否允许重新分发原始文件、修改后文件或衍生配置。
- 是否允许商业使用，以及署名、展示范围等附加条件。
- 授权证明在本地的保存位置。
- 无法确认的事项和最终准入结论。

以下资产不得作为正式 M3 资产：

- 从游戏客户端直接解包且没有明确授权依据的模型、贴图、动作或语音。
- 来源不明、无法联系作者或只有转发链接的模型和声音权重。
- 未经说话者同意制作或提供的声音克隆资产。
- 许可条款与本项目预期用途冲突的资产。
- 要求将专有资产提交到公开仓库才能运行的资产方案。

模型作者的许可不必然覆盖底层角色知识产权。若许可只足以支持本地个人使用，
则不得据此推定可以公开发布、公开展示或商业化。未来扩大使用范围时必须重新
审查。

## 仓库与本地目录边界

### 可以提交

- `doc/` 下的接入、验收和故障排查文档。
- 不含密钥、本机绝对路径和专有内容的配置模板。
- 资产通过审核后所需的最小元数据和表情名称映射；其是否可提交仍需符合资产
  许可。
- 不包含模型、权重或音频内容的自动化检查。

### 必须保持本地且受 Git 忽略

- `live2d-models/elysia-local/` 下的模型、贴图、动作和表情文件。
- `private/voice/` 下的参考音频、提示文本和声音相关记录。
- `private/m3/asset-inventory.local.md` 及 `private/m3/license-notes/`。
- GPT-SoVITS 权重、服务私有配置和其他第三方模型。
- `conf.yaml` 中的 API Key、本机路径和私有服务配置。

GPT-SoVITS 建议安装在仓库之外，例如 `D:/AI/GPT-SoVITS/`，并作为独立
进程运行。GPT-SoVITS 软件代码的 MIT 许可不自动覆盖第三方权重、训练数据、
参考音频或声音身份。

在线声音模型的 API Key、账户信息和授权证据同样必须保持本地。公开仓库只可
保存无密钥配置模板、公开模型标识和适配器代码；服务平台允许调用不等于该
声音模型的训练数据、角色身份或公开展示用途已经获得授权。

## 文件安全与可追溯性

每个资产包在使用前必须：

1. 保留原始下载来源，不运行来源包中不必要的脚本或可执行文件。
2. 使用 Windows Defender 或当前系统安全软件完成扫描。
3. 为主要模型、权重和参考音频记录 SHA-256 摘要。
4. 只从可信来源加载 GPT-SoVITS/PyTorch 权重。
5. 解压后检查是否出现超出资产范围的脚本、可执行文件、符号链接或异常路径。

PowerShell 摘要命令：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath "D:\path\to\asset.file"
```

摘要用于识别本地实际验收的文件版本，不替代数字签名或许可证证明。

## Live2D 技术准入信息

进入 M3.1 前至少确认：

- 主入口 `*.model3.json` 的相对路径和 Cubism 版本。
- 所有贴图、物理、姿势、动作和表情引用均能在本地解析。
- 模型允许本项目所需的本地加载、参数配置和表情映射。
- 口型参数存在并可以被当前前端驱动。
- Idle Motion 组、可用表情名称或索引、默认表情、推荐缩放与位置。

M3.0 不修改 `model_dict.json`，也不提前假设表情索引或 Motion 组。

## GPT-SoVITS 技术准入信息

进入 M3.3 前至少确认：

- GPT、SoVITS 权重的文件名、版本、来源、摘要及使用权限。
- 参考音频来源合法、音质可用，并具有逐字匹配的提示文本。
- 说话者已同意相应的声音建模和本项目使用范围。
- 预期语言为中文，服务能够通过本机 `127.0.0.1` 启动。
- 若改为局域网 GPU 主机，参考音频路径位于 GPT-SoVITS 服务所在主机。

首轮集成优先使用非流式 WAV、`batch_size: 1`，验证现有
`gpt_sovits_tts` 适配器后再决定是否需要最小修改。

## 在线声音模型技术准入信息

在线 TTS 作为本地 GPT-SoVITS 的可选替代路径时，至少确认：

- 服务 URL、模型名称、声音模型 ID、账户与调用方式来自服务官方说明。
- API Key 只存在于进程环境变量或受 Git 忽略的 `conf.yaml`。
- 适配器不会在启动、请求或异常日志中输出 API Key、请求正文或供应商响应体。
- 输出格式与文件扩展名一致，并对超时、401、402、429 和无效音频给出明确错误。
- 保留已验收的本地 TTS 回退，在线服务不可用时无需修改核心会话链。
- 声音模型的来源、角色权利、公开展示和商业使用范围单独审查，不能仅凭平台
  页面可调用或订阅套餐说明推定已获授权。

## M3.0 准入检查

完成本地资产登记后执行：

```powershell
git check-ignore -v live2d-models/elysia-local
git check-ignore -v private/voice/reference.wav
git check-ignore -v private/m3/asset-inventory.local.md
git status --short
```

M3.0 通过条件：

- Live2D 与声音资产分别具有明确状态和使用范围。
- `approved` 或 `restricted` 资产具有可核验的来源与授权记录。
- 本地文件摘要和安全检查已记录。
- 所有专有资产、凭据和本机路径继续受到 Git 忽略。
- 仓库中没有新增模型、贴图、权重、参考音频或授权证明。
- 未修改核心会话链、通用 Character 架构或未知资产的模型映射。

如果当前只有一个资产类别通过，可以进入该类别的独立技术验证，但 M3.0 总体
状态保持“部分通过”，直到两个类别都有明确结论。
