# Elysia M5.2 本地存储与上下文注入验收

更新日期：2026-08-12

当前状态：**实现与自动化验收通过**。

## 固定范围

本里程碑只完成 M5 技术设计中的本地存储和只读上下文注入，不提前实现
M5.3 显式自然语言记忆命令，也不实现 M5.4 前端管理界面。

- 数据仍按 `(profile_id, character_conf_uid)` 隔离；
- 功能默认关闭，只对 `basic_memory_agent` 单人非代理对话生效；
- 不修改永久 Persona 或 Agent 基础 system prompt；
- 不引入网络调用、数据库、向量检索或自动事实抽取；
- 存储和上下文故障按空记忆降级，不阻塞原有对话链路。

## 实现结果

- [x] 受控相对目录和安全作用域路径校验；
- [x] 每个作用域独立 JSON 文档、进程内共享锁和 revision CAS；
- [x] 同目录唯一临时文件、刷新落盘、结构复验和原子替换；
- [x] 最近一次有效版本备份，以及主文件损坏后的受控恢复；
- [x] 文件大小、schema、文档作用域和符号链接边界校验；
- [x] 按类别优先级与更新时间生成确定性的只读上下文；
- [x] 单条和总上下文字符预算，以及提示边界转义；
- [x] `ServiceContext` 初始化、作用域缓存、配置切换和连接缓存接入；
- [x] 每轮 LLM 调用动态读取并组合记忆上下文；
- [x] 普通、Claude MCP、OpenAI MCP 与 prompt-mode 调用路径一致生效；
- [x] 群聊元数据显式关闭注入，代理和非 Basic Agent 同样关闭；
- [x] 读取异常、初始化异常和 provider 异常均脱敏并降级为空上下文。

## 退出结论

M5.2 的代码和自动化退出条件已经满足：通过测试预置的事实可以由新的 Store
实例读取，并在单人对话的每轮 LLM 调用中动态注入；关闭、空记忆、群聊、代理
和故障场景均回退到第一阶段行为。

M5 整体尚未关闭。下一步是 M5.3：实现显式记忆命令、业务增删改查、敏感内容
拒绝和操作结果协议；之后才进入 M5.4 管理界面与人工语音验收。
