# Elysia M5.4.2.5.1 原子配置写入器验收

更新日期：2026-08-14

当前状态：**实现与自动化验收通过**。

## 1. 固定范围

本步骤只负责将记忆总开关安全地持久化到项目根目录的 `conf.yaml`：

- 固定写入 `memory_config.enabled`；
- 使用 `expected_enabled` 执行 compare-and-set；
- 先写同目录临时文件，再以原子替换提交；
- 在提交前完成完整配置校验和临时文件回读校验；
- 对配置内容、路径、密钥和异常正文执行日志脱敏。

本步骤不修改运行时 `ServiceContext`，不向管理控制器注入端口，不改变冻结的
WebSocket v1 协议，也不实现前端管理界面。运行时同步和正式端口接入属于后续
M5.4.2.5 子步骤。

## 2. 实现结果

### 2.1 写入契约

- [x] 新增不可变的 `AtomicConfigWriteResult`；
- [x] 结果区分 `success`、`rejected` 和 `failed`；
- [x] 预期状态不匹配时返回 `setting_conflict`；
- [x] 目标状态与磁盘状态相同时幂等成功且不重写文件；
- [x] 配置读取失败时允许 `enabled` 为 `null`，避免伪造未知磁盘状态；
- [x] 入参只接受严格布尔值。

### 2.2 原子写入流程

- [x] 配置路径由服务端项目根目录固定派生，调用方不能指定文件名或作用域；
- [x] 单个写入器实例使用 `asyncio.Lock` 串行化请求；
- [x] 阻塞文件操作通过工作线程执行；
- [x] 原配置和目标配置均通过完整 `Config` 模型校验；
- [x] 只在深拷贝中修改 `memory_config.enabled`；
- [x] 通过模型归一化比较确认其他配置语义未变化；
- [x] 在 `conf.yaml` 同目录创建唯一隐藏临时文件；
- [x] 临时文件使用 UTF-8、`safe_dump`、`flush` 和 `fsync`；
- [x] 文件句柄关闭后重新读取、解析并验证临时文件；
- [x] 提交前检查正式文件未被外部改写；
- [x] 使用 `os.replace` 作为唯一提交点；
- [x] 所有提交前失败均保留正式文件并清理临时文件。

### 2.3 配置与隐私保护

- [x] `${ENV_VAR}` 只在内存中的校验副本内解析；
- [x] 环境变量的实际密钥不会替换占位符写回磁盘；
- [x] 不创建可能长期残留敏感配置的永久备份；
- [x] 失败日志只包含处理阶段和异常类型；
- [x] 日志不包含 YAML 正文、配置路径、环境变量值或异常正文。

## 4. 已知限制

- PyYAML 会保留配置数据和键顺序，但不会保留注释、引号风格或原始排版；
- 当前并发锁覆盖同一进程内共享的写入器实例，不提供跨进程文件锁；
- 原子提交保证以操作系统的 `os.replace` 能力为边界，不承诺网络文件系统具备相同语义；
- 配置文件要求能够以 UTF-8 或带 BOM 的 UTF-8 解码；
- 本步骤只确认磁盘提交，尚不代表运行时服务已经同步到新开关状态。

## 5. 退出结论

M5.4.2.5.1 已完成原子配置写入器。正式配置只会在目标内容完成写入、同步、回读和
完整校验后通过单一原子替换提交；冲突、幂等和操作失败均返回内容无关的稳定结果，
且不会把解析后的密钥或失败详情写入日志。

下一步可进入 M5.4.2.5.2：实现 `MemorySettingUpdatePort` 适配与运行时同步编排，明确
“磁盘提交成功、运行时同步失败”时的补偿和响应语义。该后续步骤不应把写盘逻辑重新
分散到控制器或 WebSocket 处理器中。
